# 中文

## 黑熊 Obear 個人網站 — 前端

黑熊（吳思彥，Obear）的個人網站，部署在 GitHub Pages（`https://obearwu.github.io/ObearSite/`）。內容由後端 `ObearWu/ObearSite-backend`（Private repo）管理與發布。這份文件分成兩個獨立的部分：

- **[專案報告](#專案報告)**：這個 repo 裡的檔案是怎麼來的。
- **[架設 SOP](#架設-sop)**：本機怎麼開、怎麼部署。

系統整體架構、資料庫、發布流程、驗證方式的完整說明見後端 README。

---

## 專案報告

### ⚠️ `index.html` 和 `sitemap.xml` 是產生出來的，不要手動修改

這兩個檔案由後台的「發布網站」按鈕自動產生並提交到這個 repo（commit 訊息是「發布網站內容（…，從後台）」）。手動修改會在下次發布時被蓋掉。

- 要改文字、集數、服務、FAQ → 到後台 `admin.html` 改，再按「發布網站」。
- 要改版面、CSS、圖片位置 → 改後端 repo 的 `templates/index.html.j2`、`templates/site.css`，部署後端後再發布一次。

### 為什麼網站是靜態 HTML

網站擁有者要求搜尋引擎與 AI 搜尋看得到完整內容。很多 AI 爬蟲不執行 JavaScript，所以所有內容（23 集 Podcast、服務、FAQ、描述人物與節目的 JSON-LD 結構化資料）都直接寫在 HTML 裡，不靠 API 載入。網站因此完全不依賴後端，後端休眠時照樣秒開；只有洽談表單會呼叫後端。

### 跟原本 Artifact 的差別

畫面與原本的 Claude Artifact 逐元素比對過，桌機、手機、深色模式都一致（見後端 README）。差別只有：

- 聯絡區底下新增洽談表單（送到後端 `POST /api/public/inquiries`，成功顯示「收到了，謝謝你！」）。
- 集數卡片全部寫在 HTML 裡，「看全部集數」改成用 CSS 展開，而不是用 JavaScript 產生。
- 補上 canonical、Open Graph、`sitemap.xml`、`robots.txt`，圖片移到 `assets/`。

### 後台頁面（admin.html）

前台沒有連結指向它，頁面加了 `noindex`，`robots.txt` 也擋掉它；真正擋住未授權的人的是後端——每支後台 API 都檢查登入與權限。用 Google 登入（跟 TaiwanLARP 共用同一組 OAuth Client ID），分頁有 Podcast 集數（含「從 SoundOn RSS 同步」）、經歷、合作服務、常見問題、頁面文字、洽談、使用者；頂端的發布列顯示有沒有未發布的修改，並提供「預覽網站」與「發布網站」。

### 檔案結構

```
index.html      網站（由後台發布產生）
sitemap.xml     給搜尋引擎的網站地圖（由後台發布產生）
robots.txt      允許爬取、擋掉 admin.html、指向 sitemap
admin.html      後台（單一檔案，手動維護）
assets/         圖片：hero、stage、kid、cover、tools、drumstick
```

## 架設 SOP

### 本機開啟

先照後端 README 的 Part A 啟動後端（`http://127.0.0.1:5001`），再在這個資料夾執行：

```bash
python3 -m http.server 8000
```

打開 `http://localhost:8000/`（網站）或 `http://localhost:8000/admin.html`（後台）。用 `localhost` 開的時候，洽談表單和後台會自動改打本機後端。不要用 `127.0.0.1` 開，Google 登入不接受 IP 位址。

### 部署

repo 設定 **Settings → Pages** → Deploy from a branch → `main` / `/ (root)`。之後：

- `admin.html`、`assets/`、`robots.txt` 的修改：照一般方式 commit、push。
- `index.html`、`sitemap.xml`：由後台「發布網站」自動 commit。手動 push 之前先 `git pull`，避免跟後台的發布衝突。

# English

## Obear Personal Website — Frontend

The personal website of Obear (吳思彥, "黑熊"), served by GitHub Pages at `https://obearwu.github.io/ObearSite/`. Content is managed and published by the backend `ObearWu/ObearSite-backend` (private repo). Two independent parts:

- **[Project Report](#project-report)**: where the files in this repo come from.
- **[Setup Guide](#setup-guide)**: running locally and deploying.

See the backend README for the full architecture, database, publishing flow, and verification.

---

## Project Report

### ⚠️ `index.html` and `sitemap.xml` Are Generated — Don't Edit Them by Hand

The admin page's "Publish" button generates both files and commits them here (commit message "發布網站內容（…，從後台）"). Manual edits are overwritten on the next publish.

- Text, episodes, services, FAQ → edit in `admin.html`, then publish.
- Layout, CSS, image placement → edit `templates/index.html.j2` / `templates/site.css` in the backend repo, deploy the backend, then publish.

### Why the Site Is Static HTML

The owner wants search engines and AI search to see the full content. Many AI crawlers don't run JavaScript, so everything (23 Podcast episodes, services, FAQ, and JSON-LD structured data about the person and the show) is written directly into the HTML rather than loaded from an API. The site therefore doesn't depend on the backend at all and loads instantly even when the backend is asleep; only the inquiry form calls it.

### Differences from the Original Artifact

The page was compared element by element with the original Claude Artifact on desktop, mobile, and dark mode, and matches (see the backend README). The only differences:

- A new inquiry form under the contact section (posts to `POST /api/public/inquiries`; shows "收到了，謝謝你！" on success).
- All episode cards are in the HTML; "看全部集數" expands them with CSS instead of generating them with JavaScript.
- Added canonical, Open Graph, `sitemap.xml`, `robots.txt`; images moved to `assets/`.

### Admin Page (admin.html)

Nothing on the site links to it, it has `noindex`, and `robots.txt` excludes it; what actually keeps unauthorized people out is the backend, which checks sign-in and permissions on every admin API. Google sign-in (sharing TaiwanLARP's OAuth Client ID); tabs for episodes (with "從 SoundOn RSS 同步"), timeline, services, FAQ, page texts, inquiries, and users; the bar at the top shows whether there are unpublished changes and offers "Preview" and "Publish".

### File Layout

```
index.html      The site (generated by publishing)
sitemap.xml     Sitemap for search engines (generated by publishing)
robots.txt      Allows crawling, excludes admin.html, points to the sitemap
admin.html      Admin page (single file, maintained by hand)
assets/         Images: hero, stage, kid, cover, tools, drumstick
```

## Setup Guide

### Running Locally

Start the backend per Part A of the backend README (`http://127.0.0.1:5001`), then in this folder:

```bash
python3 -m http.server 8000
```

Open `http://localhost:8000/` (site) or `http://localhost:8000/admin.html` (admin). On `localhost` the inquiry form and admin page automatically target the local backend. Don't use `127.0.0.1`; Google sign-in doesn't accept IP origins.

### Deploying

Repo **Settings → Pages** → Deploy from a branch → `main` / `/ (root)`. Then:

- Changes to `admin.html`, `assets/`, `robots.txt`: commit and push as usual.
- `index.html`, `sitemap.xml`: committed automatically by "Publish". `git pull` before pushing manually to avoid conflicting with a publish.
